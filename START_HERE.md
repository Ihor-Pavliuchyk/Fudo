# Fudo — спільна версія (дизайн Нестора + Андрій + Ігор + Юрій)

## Готовий архів

Розпакуйте ZIP, відкрийте папку `fudo_full_upgrade` у VS Code. **Не відкривайте вкладений ZIP**: тепер усе вже всередині одного застосунку.

У цьому проєкті є:
- `/` — адаптивна головна за скриншотами Нестора: пошук і фільтри демонстраційних пропозицій, CTA, відгуки-приклади;
- `/maps` — карта магазинів, плюс API магазинів і гуртожитків від Андрія;
- `/group-orders` — браузерна демонстрація групових замовлень Ігоря, **без реальних платежів**;
- `/register`, `/login`, `/forgot-password`, `/reset-password`, `/verify-email` — акаунти Юрія;
- `/settings`, `/settings/profile`, `/settings/notifications`, `/settings/support`, `/settings/about` — налаштування Юрія.

Оригінальний логотип наданий командою; використаний у спільній шапці. Модуль каталогу Маркіяна ще відсутній.

## Як запустити (Node.js 22.12+, PostgreSQL)

1. У терміналі в кореневій папці `fudo_full_upgrade` запустіть `npm install`.
2. Для локальної PostgreSQL (якщо є Docker) — `docker compose up -d`. Або використайте свою PostgreSQL БД.
3. Скопіюйте `.env.example` у `.env`, встановіть `DATABASE_URL`, `APP_URL=http://localhost:3000` і **випадково згенерований** `AUTH_SECRET` (команда `npx auth secret`). Не зберігайте паролі чи секрети у Git.
4. Виконайте `npx prisma generate` та `npx prisma migrate dev --name init_fudo_accounts`. Перша команда створює Prisma-клієнт, друга створює таблиці для акаунтів. У командній БД спершу погодьте міграцію.
5. Запустіть `npm run dev` і відкрийте `http://localhost:3000`. Сторінка реєстрації — `http://localhost:3000/register`.

У локальному режимі без Resend посилання на скидання пароля й підтвердження пошти пишуться в термінал сервера (тільки розробка). Для справжніх email потрібно вказати `RESEND_API_KEY` і коректний `EMAIL_FROM`.

## Перевірки

`npm test` перевіряє бізнес-логіку групових замовлень, навігацію, бренд і структуру інтеграції. `npm run typecheck` та `npm run build` запускайте після встановлення залежностей і `npx prisma generate`. Для перевірки акаунтів у браузері необхідна працююча PostgreSQL.

## Що поки не підключено

**Групові замовлення залишаються локальною демонстрацією на `localStorage`**: у них немає реальних спільних учасників, сесій чи оплат. Акаунти вже мають спільний `FudoUser.id` у БД, але прив'язка замовлень до нього — наступний етап роботи Ігоря. Внутрішні сповіщення є в акаунті, проте події від модуля замовлень/магазинів іще не підключено.

Профіль, сповіщення і звернення зберігаються у PostgreSQL. Звернення до підтримки поки не мають панелі оператора. Документи «Правила» й «Політика» — чернетки, перед публічним запуском їх треба перевірити. Інформація в `/settings/about` доступна без входу; для персональних сторінок потрібен акаунт.

## Безпека

Не використовуйте тестовий пароль PostgreSQL з compose у продакшені. У продакшені налаштуйте HTTPS, безпечні секрети, захист email, реальні контакти підтримки, міграції й комплексне тестування. Не збирайте платіжні реквізити в цьому демо.
